# FeliCa (おサイフケータイ) - from L-01K L-01K20k
# The apks and jars are byte-identical on both japanese handsets; only the
# etc/felica/*.cfg differ, and those are carried per SKU further down.
#
# Everything here is signed with FeliCa Networks' key, and that signature is
# what the ACLs check: felica_access.xml names it on the NFC side, and MFC
# checks the calling app's own against the permit it was handed. Keep the
# menu apps PRESIGNED - the permit is issued against that key, and a repacked
# MobileFeliCaMenuMainApp would not verify.
#
# MobileFeliCaClient is the exception: it is repacked to restore its own
# logging (see extract-files.py) and comes back platform-signed. Nothing
# checks *its* signature except felica_access.xml, which NfceeAccessControl
# also satisfies for platform-signed callers.
#
# These stay on /product because com.felicanetworks.felica.xml names
# /product/framework/com.felicanetworks.felica.jar by absolute path; there is a
# real product partition here, so nothing has to move.
#
# The "felica" system service these need is now in packages/apps/Nfc; see
# docs/felica-port.md for how far Osaifu-Keitai actually gets.

# MobileFeliCaMenuMainApp keeps its dex deflated, which a privileged app is not
# supposed to do - soong's check_prebuilt_presigned_apk rejects it. Storing it
# would be safe for the signature, since it carries a v1 JAR signature and no
# APK Signing Block, and v1 signs entry contents rather than how they are
# packed - but the apk would then have to be realigned, and the only thing the
# check buys is that ART can map the dex instead of unpacking it once into
# dalvik-cache. Not worth rewriting a signed blob over, so the check is skipped.
# MobileFeliCaClient is repacked anyway, so it comes out of that clean.
